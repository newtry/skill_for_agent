# 方案检查表

用于新功能、跨模块变更和高风险 Bug。小型单模块修改只取相关项。

## 需求基线

- [ ] 业务目标和成功指标
- [ ] 用户角色、调用方和使用场景
- [ ] 功能规则、前置条件和结果
- [ ] 状态转换、异常、取消、重试和补偿
- [ ] 非功能约束：性能、并发、兼容性、审计、可观测性
- [ ] 验收条件和明确不做的范围
- [ ] 开放问题、假设和冲突来源

## DDD 与模块落地

需要时使用 `$ddd-strategy-design`，并确认：

- [ ] 统一语言和歧义术语
- [ ] 领域事件、命令、参与者和时间约束
- [ ] Core/Supporting/Generic 子域分类
- [ ] 限界上下文及候选模块
- [ ] 上下文映射、ACL、同步/异步集成
- [ ] 聚合根、不变式、事务边界和最终一致性
- [ ] API/Biz 归属、数据所有权、权限和租户边界
- [ ] 迁移、回滚、幂等、重试和失败恢复

## 测试基线

需要时使用 `$derive-test-cases`：

- [ ] 每条验收条件至少关联一个测试或说明不适用原因
- [ ] 主流程、异常、边界、重复请求和部分失败
- [ ] 角色、租户、数据权限和越权
- [ ] 持久化、事务、事件、外部调用和重试
- [ ] 回归范围、测试数据、自动化层级和环境依赖
