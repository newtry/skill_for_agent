# 验证矩阵

选择能证明风险已覆盖的最小验证集合，并报告实际命令和结果。

| 变更类型 | 首选验证 | 必要补充 |
| --- | --- | --- |
| 单模块业务逻辑 | 目标模块单元测试 | 边界、异常和回归测试 |
| API/Controller | Service 测试 + API 测试 | 权限、租户、参数校验、错误 envelope |
| 跨模块 API | 上下游模块测试、编译 | 契约兼容、超时、重试、幂等 |
| 数据库/迁移 | 迁移执行和回滚检查 | 旧数据、重复执行、索引和数据量 |
| 批量导入/库存/金额 | 小数据集 + 边界数据集 | 大数据量、重复、部分失败、事务恢复 |
| 消息/定时任务 | handler/service 测试 | 重复消费、失败重试、死信和观测 |
| 权限/租户/认证 | 正向和越权测试 | 跨租户、匿名、缓存和审计 |
| 前端交互 | 关键路径手工或 E2E | 空态、错误态、移动端和刷新恢复 |

## Maven 约定

在对应 Maven 根目录执行，不要从错误的聚合目录猜测模块：

```bash
mvn -pl <module> -am test
mvn -pl <module> -am -DskipTests package
mvn -pl <module> -am -Dtest=<TestClass> -Dsurefire.failIfNoSpecifiedTests=false test
```

框架依赖缺失时，先按项目指令安装 `guanyi-leanboot`，再构建产品；不要把依赖缺失误判为代码失败。对于未能运行的测试，标记为环境阻塞并保留日志摘要。

## 结果格式

报告：命令、退出状态、关键输出、覆盖的风险、未覆盖项和下一步。不要只写“测试通过”或“应该没问题”。
