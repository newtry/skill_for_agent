# 为什么提示词技巧不是 AI 编程的核心竞争力

提示词当然重要，但它很容易被误解成一套神秘的措辞技巧：加几个角色、换一种格式、要求模型“深度思考”，就能稳定得到好结果。

我的经验是，真正决定效果的通常不是句子写得多漂亮，而是工程师是否知道要提供什么事实、划定什么边界、要求什么证据。

## 同一句话在不同项目里结果不同

“帮我加一个接口”在示例项目里可能足够，在 ERP 里却需要说明入口、模块、租户、账套、兼容性和验收。模型结果的差异，来自问题空间不同，不是某个神奇关键词。

## 更高阶的提问是工程准备

好的任务说明包含目标、事实、范围、约束、开放问题、验收条件和授权。好的工作区包含项目规则、相似实现、测试入口和交接记录。好的反馈包含实际 diff、命令、数据结果和失败证据。

这些东西比“请你像专家一样回答”更能改变结果。

## 核心能力仍然是判断和验证

工程师要能识别业务不变量，知道数据粒度，理解事务、权限、依赖和部署，判断测试是否真的覆盖风险。AI 可以放大这些能力，也会放大缺少这些能力时的错误速度。

所以 AI 编程的竞争力不是谁会背更多提示词，而是谁能把模糊问题变成可验证任务，再把结果纳入真实工程流程。
