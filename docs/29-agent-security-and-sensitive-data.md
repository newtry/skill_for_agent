# 如何防止 AI 泄露思考过程、敏感数据和内部字段

> 系列导航：[完整目录](00-series-titles.md)

Agent 上线后，最容易被忽视的风险不是模型回答错一个商品名称，而是它把不该展示的内容带给了不该看到的人：内部字段、原始 SQL、系统提示词、其他租户数据、日志中的手机号或第三方密钥。

我后来把安全问题从“提示词里写一条禁止泄露”提升为一条完整链路：输入、检索、工具、模型、输出和日志，每一层都有自己的边界。

## 一次上线前回放暴露了三个出口

在一次安全回放中，页面最终答案没有显示敏感数据，看起来已经通过。但检查完整链路后发现，工具返回里仍包含内部字段，调试日志记录了原始参数，失败响应还把内部 SQL 错误直接交给模型总结。数据没有从页面泄露，却已经进入模型上下文和日志系统。

修复也因此分成三层：查询工具只返回允许展示的字段；日志只记录脱敏摘要和追踪标识；输出适配层把内部异常转换成业务错误。只在最终文本上做关键词过滤，无法覆盖这些出口。

## 不要把展示安全交给模型自觉

模型可以被诱导，也可能把工具返回的原始字段直接复述出来。数据访问应先在工具和服务端完成租户、角色、字段和业务范围过滤，模型拿到的输入就应该尽量是可展示的最小数据。

输出层还要做敏感字段脱敏、内部错误替换和格式校验。原始 SQL、系统提示词和内部思考过程不应直接返回给用户；需要解释时，输出业务层面的结果、依据和可追踪编号。

## 日志和 Telemetry 也是数据出口

即使页面没有泄露，调试日志、工具参数、Telemetry（遥测与链路数据）和评测样本也可能把敏感数据保存下来。Agent 调用日志应记录必要的审计信息，例如调用人、租户、工具名、参数摘要和结果状态；密码、令牌、完整身份证件和原始业务内容要脱敏或不记录。

## 输入注入不能只靠一段提示词

用户可能要求模型忽略规则，工具返回的数据也可能包含诱导文本。系统需要区分用户输入、业务数据、工具结果和系统指令，并在工具执行前重新检查权限和参数。模型说“已经授权”不等于系统真的授权。

## 安全检查清单

```text
身份：调用者、租户、角色和数据范围是否明确？
输入：是否有注入、越权或恶意指令？
工具：参数、字段、写操作和幂等是否受限？
输出：是否泄露内部字段、原始错误、提示词或敏感数据？
日志：请求、工具、结果和 Telemetry 是否脱敏？
审计：谁在什么时间通过什么工具做了什么？
```

安全不是让 Agent 变得沉默，而是让它在可展示的数据和可授权的动作范围内工作。提示词能表达意图，权限、工具和日志治理才能真正形成保护。
