# 让 AI 听懂行业黑话：服装批发业务术语库的建设实践

业务人员说“拿一手货”“看波段”“这个款走份”“查一下老客”，技术人员和通用模型未必知道这些词在当前公司的具体含义。Agent 如果听不懂行业黑话，回答再流畅也无法进入工作流程。

我在服装批发场景里意识到，术语库不是简单的词典，而是业务语言、数据对象和操作边界之间的翻译层。

## 同一个词可能对应不同对象

“款”可能指商品款号，也可能指一个款式下的颜色尺码组合；“库存”可能是物理数量、可售数量或已经预占后的可用数量；“老客”可能由交易次数、最近购买时间或人工标签定义。术语必须带定义、同义词、适用场景和不能混用的近义词。

## 术语要连接到数据和权限

每个词除了解释，还应说明它对应的系统对象、查询入口、关键维度和允许的动作。例如“可售库存”需要明确门店、账套、仓库、预占和冻结规则；“销售额”需要明确时间、退款和含税口径。

这样 Agent 在检索或调用工具前，才能把自然语言翻译成受控参数，而不是凭相似文字猜字段。

## 用真实对话持续修订

术语库最初不可能完整。可以从历史会话、客服问法、报表名称和错误检索中收集候选词，让业务人员确认定义，再加入示例和反例。若模型频繁把两个词混淆，应优先补充边界说明，而不是继续堆同义词。

```text
请整理以下业务术语：
术语、定义、同义词、反例、对应数据对象、查询维度、适用角色、允许动作、来源和待确认项。
对于无法确认的词只列候选解释，不直接写入正式术语库。
```

术语库的目标不是让 Agent 说得更像业内人士，而是让它在正确的业务口径下检索和行动。语言统一后，模型、工具、报表和团队才有可能真正对齐。
