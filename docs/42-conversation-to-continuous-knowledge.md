# 从一次性对话到持续知识沉淀：文档、记忆、Skill 与任务板

> 系列导航：[完整目录](00-series-titles.md)

如果 AI 每次都重新回答同一类问题，说明个人使用经验还停留在聊天里。真正成熟的使用方式，是把一次对话产生的有效内容放到合适的长期载体中。

## 核心判断：知识沉淀的关键是路由和生命周期

不是所有有用信息都应该长期保存，也不是所有长期信息都应放进同一个文件。知识需要根据稳定性、作用范围、执行方式和责任归属进入不同载体，并经历候选、确认、生效、复核和淘汰。没有生命周期的“记忆”只会持续累积过期上下文。

## 我也把错误经验沉淀成过“长期规则”

一次排查中，为了绕过本地环境限制，我临时使用了一条特殊启动命令。它在当时有效，后来却被写进项目规则，导致其他环境也照搬这条命令。临时方案一旦失去适用条件，就从帮助变成了新的上下文噪声。

这件事让我给知识增加两个属性：来源和有效范围。来自一次故障的结论，要注明适用版本、环境和验证时间；只有跨任务稳定成立并经过复核的事实，才进入长期规则。

那条特殊启动命令后来被移出项目规则，保留在故障记录中，并标明只适用于某个本地环境。与此同时，我们补充了真正稳定的规则：正常构建目录、标准启动方式以及环境缺失时的诊断步骤。沉淀不是把旧内容换个文件保存，而是重新判断它的适用级别。

## 不同经验放到不同地方

项目规则放稳定事实；任务文档放当前需求、验收和开放问题；交接记录放阶段状态；Skill 放跨任务可复用的方法；任务板放责任、状态、优先级和交付证据；测试和脚本则把关键规则变成可执行约束。

没有一种文档适合承载所有记忆。把所有内容都丢进一个大文件，最终会比没有记忆更难使用。

| 内容 | 载体 | 失效信号 |
| --- | --- | --- |
| 项目稳定事实 | 项目规则 | 模块、命令或环境变化 |
| 当前任务状态 | 任务板、交接记录 | 任务结束或现场变化 |
| 可复用专业流程 | Skill | 输入、工具或门禁变化 |
| 可执行业务约束 | 测试、脚本 | 契约或业务规则变化 |

还可以补充两个容易混淆的载体：决策记录保存“为什么当时这样选”，但不自动成为当前规则；参考资料保存背景知识，却不能覆盖当前项目事实。载体选择决定 AI 应该把内容当成强约束、当前状态、方法建议还是历史解释。

## 沉淀前先问三个问题

这条经验是否会在未来重复出现？是否能用明确规则表达？是否需要脚本、模板或工具支持？重复且稳定的事实进入项目规则；专业流程进入 Skill；可以自动检查的内容优先变成测试或脚本。

我会再补充三个问题：适用于一个任务、一个项目还是多个项目？谁有权确认它？什么变化会让它失效？如果无法回答来源、范围和责任人，内容只能留在候选区，不能进入权威知识。

```text
会话发现
-> 提取候选事实或方法
-> 核对来源与适用范围
-> 选择载体和责任人
-> 评审后生效
-> 在真实任务中使用和验证
-> 定期复核、降级或删除
```

不同候选的升级门槛也不同：

| 候选内容 | 目标载体 | 生效前最低证据 |
| --- | --- | --- |
| 构建目录和模块边界 | 项目规则 | 当前代码、脚本或 CI 证据 |
| 一次任务当前进度 | 交接/任务板 | 基线、diff 和运行状态 |
| 跨任务处理方法 | Skill | 多个真实任务与边界样本 |
| 不可破坏的技术约束 | 测试/脚本 | 可重复失败与通过样本 |
| 历史取舍理由 | 决策记录 | 决策人、背景和替代方案 |

这能防止一个经验仅仅因为“很有用”就进入最高权威层。稳定事实、阶段状态和方法经验有不同的验证方式，也有不同的失效速度。

## 知识之间出现冲突怎么办

新任务可能推翻旧规则，项目规则也可能与 Skill 示例冲突。系统需要显示来源、版本、更新时间和优先级，并在冲突时停止自动写入。修复应发生在权威载体，而不是让当前会话临时选择一条继续。

知识检索也不能只按语义相似度返回。当前项目、模块、版本、环境和任务阶段都应参与过滤；一条高度相似但适用于旧协议的经验，比没有检索结果更危险。

## 知识沉淀也需要淘汰机制

定期检查规则是否过期，合并重复模板，移除只适用于一次任务的细节，并保留来源和最后验证时间。没有维护责任的知识库，最后会成为另一种上下文噪声。

可以根据使用和验证记录触发复核：长期未命中的规则可能已经失去价值；频繁命中但总被人工纠正的规则可能已经错误；依赖模块、工具或协议发生变化时，相关知识应批量标记待复核，而不是继续默认生效。

## 怎样证明知识正在产生复用价值

我会观察同类问题的重复解释次数、规则冲突率、过期知识命中率、人工纠正率和由知识触发的自动检查数量。知识资产的目标不是文件数量增长，而是下一次任务能更快得到正确边界，并减少同一种返工。

AI 可以提取候选、发现重复和识别可能过期的内容；项目、业务和能力负责人确认权威知识；测试与脚本负责把关键约束变成执行门禁。沉淀完成的证据，是内容进入了合适载体、带有来源和失效条件，并在后续任务中被验证使用。

```text
请处理【知识候选】：

1. 区分事实、阶段状态、方法、决策理由和临时方案；
2. 说明来源、适用项目/版本/环境、确认人和失效条件；
3. 在项目规则、任务板、交接、Skill、测试脚本或历史记录中选择载体；
4. 检查与现有权威知识的重复和冲突，冲突时不自动生效；
5. 设计后续验证、复核时间和淘汰方式。
```

AI 的长期价值不是记住更多聊天，而是帮助个人和团队形成“问题—决策—验证—沉淀—复用”的循环。每次任务都能让下一次更容易，使用经验才真正变成资产。
