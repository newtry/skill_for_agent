# 如何让多个 AI 工具共享同一套项目规则和研发记忆

当 Codex、Claude Code、IDE 助手和任务板机器人同时参与项目时，最容易出现的不是工具不够强，而是每个工具理解的项目不一样：一个知道 App 入口，另一个只看过 Admin 代码；一个遵守 API/Biz 边界，另一个直接引用实现类。

解决办法不是给每个工具分别写一套长提示词，而是把稳定知识放进工具都能读取的项目资产。

## 共享内容要分层

项目规则放在统一入口，例如 `AGENTS.md`，包括模块、构建、测试、接口、权限和禁止动作。任务说明记录本次目标、范围和验收。交接记录保存阶段状态。工具配置只保留各自的适配方式，不重复定义业务规则。

这样，规则只维护一份，工具差异只存在于调用和展示层。

## 共享规则必须可验证

每条重要规则都应能通过文件、命令或测试找到证据。比如“跨模块走 API”应能在 POM 和调用样例中验证；“生产操作需确认”应能在工作流门禁中看到；“租户不可越界”应有测试或数据检查。

没有证据的记忆很容易变成过期意见，被不同工具各自解释。

## 规则也会过时

定期合并重复规则，删除已失效的命令，更新模块和部署变化，并把反复纠正 AI 的经验沉淀进去。规则文件越长不代表越好；它应该优先保留那些会导致错误或返工的事实。

共享记忆的目标不是让所有工具输出完全相同，而是让它们在同一组项目边界内工作。工具可以有不同表达和擅长领域，但不能各自发明业务规则。
