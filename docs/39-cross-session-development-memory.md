# 跨会话继续开发：如何解决 AI 换会话就失忆的问题

长任务不可能永远停留在一个会话里。上下文达到限制、模型切换、工具切换或工作日结束后，下一次都需要继续。真正的问题不是 AI 没有记忆，而是我们没有把“当前做到哪里”保存成可恢复状态。

## 交接记录不需要复述全部聊天

我会保存四类信息：已确认的事实和证据，已经完成的改动和命令，未完成的问题与阻塞，下一步最小动作。不要复制整个对话，也不要只写一句“继续开发”。

```text
任务目标：
当前版本/分支：
已确认：
已修改：
已验证：
未完成/阻塞：
下一步：
```

这份记录要与项目规则和代码 diff 配合使用。记录是导航，不是事实来源；新会话仍需检查工作区和实际文件。

## 重新开始时先恢复，不要直接执行

新的 AI 会话第一步应读取交接记录、项目规则、`git status`、相关 diff 和最近测试结果，再判断历史结论是否仍然成立。如果记录和代码不一致，要以当前工作区为准并标记冲突。

## 将交接记录当作阶段产物

分析结束记录一次，实施结束记录一次，验证结束再记录一次。这样即使任务被中断，下一次也可以从最近稳定点继续，而不是从模糊的聊天记忆重新开始。

跨会话协作的核心不是让 AI 永远记住过去，而是让过去变成结构化、可核验、可更新的项目事实。
